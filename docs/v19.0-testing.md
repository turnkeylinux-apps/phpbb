# phpBB 19.0 testing

## Source and dependency decision

Debian Trixie does not publish a `phpbb3` package. A disposable Trixie probe
on 2026-08-25 found no candidate for that package. The appliance therefore
uses the official phpBB 3.3.17 full package from
`https://download.phpbb.com/pub/release/3.3/3.3.17/`. The build pins the
archive to the SHA-256 published by phpBB:

```text
ba1819a53c6a36bb9ebce8d3d0ac6c1b28687d6aa07a2ce9d8c4956da7d38874
```

Debian remains the source for PHP, Apache, MariaDB, Postfix, and their
dependencies. The initial Trixie probe selected the PHP 8.4 metapackages,
Apache 2.4.68, and MariaDB 11.8.6. The exact package revisions from the
acceptance root are recorded in the harness report's `package_source` field.

The official phpBB download page identified 3.3.17 as the maintained stable
release on 2026-08-25. The build uses the full release package because it
includes the supported dependencies and installer. A Git checkout or a
Composer reconstruction would add another dependency-resolution boundary
without improving the appliance contract.

## Test entry point

Run the exact acceptance command from the TurnKey v19 harness checkout:

```bash
TKLDEV_CONTAINER=tkldev19-wave2 \
TKL_HARNESS_STATE_DIR=/home/agent/.local/state/turnkey-v19-harness-wave2 \
TKL_HARNESS_LOCK_FILE=/home/agent/.local/state/turnkey-v19-harness-wave2/build.lock \
/sandboxed-git/turnkey/tools/test-v19-appliance phpbb \
  --source /home/agent/.local/worktrees/turnkey-apps/phpbb/wish-phpbb-v19-trixie
```

The harness builds with `RELEASE=debian/trixie` and `FAB_ARCH=amd64`, starts
the configured root through normal init in a disposable container, preseeds
the firstboot credentials, then runs `tests/v19.sh`. The report records the
source commit and archive digest, transported and build tree digests, harness
commit and digest, build mode, runtime result, updater result, limitations,
and verdict.

## Update channel and procedure

`turnkey-phpbb-check-update` is the non-destructive update check. It reads the
installed version through phpBB's CLI, discovers the highest stable 3.3.x
release from the official HTTPS index, and validates the shape and filename
binding of the official SHA-256 sidecar. It prints the installed and latest
versions, channel, package URL, and package digest. The acceptance test proves
that this command does not modify the installed version.

phpBB's supported full-package procedure is the update path. Before applying
an update, back up the database and `/var/www/phpBB`, use the checker to select
the official package and checksum, download both over HTTPS, and verify the
archive with `sha256sum --check`. Preserve `config.php`, `files/`, `images/`,
`store/`, `ext/`, and any additional styles while replacing the core files.
Then run the supported database migration from `/var/www/phpBB`:

```bash
php bin/phpbbcli.php --safe-mode db:migrate
```

Remove the restored `install/` directory after the migration and rerun the
administrator, forum, and topic smoke checks. The full procedure is also
included in phpBB's packaged `docs/INSTALL.html`.

## Limitations and deferred checks

The Docker runtime does not exercise the installer, kernel, or hardware. The
shared harness records this limitation and validates the configured Trixie
root before runtime import. Browser JavaScript and visual layout are outside
this test. The form tests use the same HTTPS endpoints, cookies, CSRF tokens,
and administrator transitions as a browser without depending on presentation.

No destructive updater apply is run against the acceptance instance because
3.3.17 is already the latest stable release. The checker verifies the eligible
channel and integrity metadata, while the disposable functional round trip
proves the current release before any future operator update.
